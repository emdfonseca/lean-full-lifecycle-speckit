## Lean Full-Lifecycle governance addendum

When creating or updating the Constitution, encode actionable project-wide
rules for:

1. one authoritative source per mutable fact;
2. progressive formalization and minimum justified ceremony;
3. living specifications and no silent spec/code divergence;
4. Red–Green–Refactor for behavioral production changes where practical;
5. behavior-focused deterministic tests and risk-shaped test depth;
6. simplicity, YAGNI, cohesion, explicit boundaries, and no premature
   abstraction;
7. secure defaults, least privilege, trust-boundary validation, secret safety,
   and risk-triggered threat analysis;
8. reliability, explicit failure handling, idempotency/concurrency semantics,
   and production observability where applicable;
9. small reviewable changes, short-lived branches/worktrees, and frequent
   integration;
10. Devbox-backed reproducibility and no undocumented global dependencies;
11. Definition of Output Done;
12. Definition of Outcome Done and asynchronous outcome validation;
13. identical quality standards for human- and agent-generated code;
14. brownfield quality ratchets and narrow, owned, expiring exceptions.

Avoid vague statements such as “write clean code” or dogma such as 100%
coverage, arbitrary function lengths, abstractions for every duplication, or
mandatory E2E tests.

What a rule must look like is below, rendered from the policy `documents.py`
enforces. Do not restate it here in other words — a second description of the
shape is the one that drifts.
> Apply the canonical installed policy under `.specify/presets/lean-full-lifecycle-governance/policy/` when present.

### The shape every principle takes

A name, one line stating the rule, then bullets using the RFC 2119 keywords MUST, MUST NOT, SHOULD, SHOULD NOT, MAY. No explanatory paragraph before the rule: if the rule needs one to be understood, it is not yet written.

**Excludes.** Anything a policy file already holds. Reference the path instead -- the constitution's own first principle requires it, and a constitution that restates policy is the drift it forbids.

`documents.py` enforces exactly this, so a principle that does not take this shape fails the check before anyone reads it.

**Write `SHOULD` when the source material states a preference.** It satisfies the contract without turning an expectation into an obligation. `MUST` binds the project, and only whoever governs the project may decide that -- never this generator, and never a validator reacting to a missing keyword.
